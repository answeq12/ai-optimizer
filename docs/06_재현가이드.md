# 재현 가이드 (다른 PC에서 ORT 최종 결과 다시 만들기)

> 대상: 팀원 PC 검증, 학술부 재현. **GPU 필요 없음.** 원 실험도 전부 CPU로 했다.
> 재현하는 것: COCO-confirm 검색(R@1/5/10)과 CIFAR-100 test 정확도 (A0 FP32 기준 모델, A1 동적, SPL-b567-k32, DA5-A0 적응 FP32, **DA5-SPL 최종**), PC CPU 속도. 최종 시험 XM3600 은 6-2절(보고서 9.2와 같은 명령).
> 최종 구성 DA5-SPL = 도메인 적응 가중치(`repro/weights/da5_chosen.pt`, 이미지·텍스트 뒤쪽 4블록, 166 MB, sha256 `repro/weights/SHA256SUMS`) + SPL-b567-k32 와 같은 양자화 처방. **가중치 파일은 100 MB 를 넘어 GitHub 저장소에 없고 Release(https://github.com/answeq12/ai-optimizer/releases)에 있다 → 2단계의 `wget` 으로 받아 `repro/weights/` 에 둔다. 없으면 reproduce.sh 가 5단계에서 멈춘다.** 직접 학습해 만들려면 `DA_TRAIN=1 bash reproduce.sh` (CPU 약 15시간 추가, COCO train2017 11.8만·CC3M 10만 장 다운로드, 디스크 약 90 GB, CPU 학습이라 값이 아주 조금 다를 수 있음)
> 판정 기준: **정확도는 제출값과 ±0.2%p 안이면 일치.** 속도는 CPU 마다 달라서 FP32 대비 배율만 본다.

## 빠른 안내 (학술부·심사용)

**재현에 쓰는 파일** (저장소에는 재현에 필요한 파일만 있다. `results/`·`logs/` 는 실행하면 새로 생긴다)

| 위치 | 역할 |
|---|---|
| `reproduce.sh` / `repro_quick.sh` / `run_pilot.sh` | 전체 재현(2~4시간) / 빠른 재현(20~30분) / 다운로드 없는 점검(2~3분) |
| `repro/` | 최종 모델 만들기(`da_build.sh`), 기대값, 분할·가중치 지문 |
| `src/`, `splits/`, `tests/` | 코드 전부, 고정된 평가·캘리브 사진 목록, SELFTEST용 가짜 데이터 |
| `results/sensitivity/groups.json` | 양자화 단계가 읽는 층 이름 목록 |
| `model_files/` | **제출 모델 파일** (베이스라인·최종 ONNX 등, 아래 참조) |
| `requirements.lock.txt` | 버전 고정 설치 목록 |
| `dfc/` | Hailo 재컴파일(선택, Hailo DFC 5.4.0 필요) |

**제출 모델 파일로 바로 평가하기** (`model_files/`, 지문 `model_files/SHA256SUMS_models.txt`)

| 파일 | 내용 |
|---|---|
| `clip_vitb16_image_fp32.onnx` (`.part0~3` 4조각) | 베이스라인 FP32, 344.9 MB |
| `DA5-SPL-b567-k32.onnx` | 최종 최적화 모델, 89.8 MB |
| `DA5_text_state.pt` | 최종 모델과 짝인 적응 텍스트 인코더 |
| `SPL-b567-k32.onnx`, `clip_vit_b_16_image_encoder.splf_b7_k32.hailo10h.hef` | 참고: 원본 가중치 SPL, Hailo-10H 컴파일 결과 |

```bash
cd model_files
cat clip_vitb16_image_fp32.onnx.part0 clip_vitb16_image_fp32.onnx.part1 \
    clip_vitb16_image_fp32.onnx.part2 clip_vitb16_image_fp32.onnx.part3 > clip_vitb16_image_fp32.onnx
sha256sum -c SHA256SUMS_models.txt && cd ..
# 아래 2~6단계(reproduce.sh)로 데이터·텍스트 임베딩을 준비한 뒤, 같은 터미널에서:
python -m src.coco_retrieval eval --model model_files/clip_vitb16_image_fp32.onnx --code SUB-A0 --split confirm --i-know-final
HALIO_MODELS_SUBDIR=models_da5 python -m src.coco_retrieval eval \
  --model model_files/DA5-SPL-b567-k32.onnx --code SUB-DA5-SPL --split confirm --i-know-final
```

최종 모델은 이미지·텍스트 인코더를 함께 적응했으므로, 검색 평가는 `models_da5` 의 적응 텍스트 임베딩(reproduce.sh 가 만든다)과 짝으로 써야 보고서 수치가 나온다. 저장소에 모델 파일이 들어 있어 `git clone` 이 약 640 MB 더 받는다.

## 0. 필요한 것과 저장 공간

| 항목 | 크기 (대략) | 둘 곳 |
|---|---|---|
| WSL Ubuntu 22.04 | 약 2 GB | C 드라이브 (자동) |
| 파이썬 환경 (torch CPU판 포함) | 약 2 GB | C (WSL 홈 `~/venvs/halio`) |
| 코드 저장소(git clone, 제출 모델 파일 포함) + 적응 가중치 | 약 760 MB + 166 MB | C (WSL 홈 `~/ai-optimizer`) |
| 데이터·모델 (COCO val2017 + 캡션, CIFAR-100, CLIP 가중치, ONNX 4개) | 약 4~5 GB | **하드디스크 권장** (`HALIO_DATA_DIR`) |
| (선택) 최종 시험: XM3600 + NoCaps 검증셋 사진 4,500장 | XM3600 약 0.9 GB + NoCaps(1 GB 넘을 수 있음) | 데이터 폴더 |

- C 에 여유 10 GB, 데이터 드라이브에 여유 10 GB 면 충분하다
- 메모리 16 GB 이상 권장 (WSL 은 기본으로 PC 메모리의 절반을 쓴다)
- 인터넷 필요 (COCO·CIFAR·CLIP 가중치·파이썬 패키지 다운로드 약 3 GB)
- **Windows 절전을 "안 함"으로.** 측정 중 절전에 들어가면 실패한다

## 1. WSL 설치 (처음 한 번, 약 10분)

PowerShell 을 **관리자로** 열고:

```powershell
wsl --install -d Ubuntu-22.04
```

재부팅 → 시작 메뉴에서 "Ubuntu 22.04" 실행 → 사용자 이름·비밀번호 만들기. 이미 WSL 이 있으면 `wsl -l -v` 로 Ubuntu-22.04 가 있는지 확인.

## 2. 코드와 적응 가중치 받기

Ubuntu 창에서:

```bash
sudo apt update && sudo apt install -y python3.10-venv git wget
cd ~ && git clone https://github.com/answeq12/ai-optimizer && cd ai-optimizer
wget -O repro/weights/da5_chosen.pt https://github.com/answeq12/ai-optimizer/releases/download/v1.0-da5/da5_chosen.pt
(cd repro/weights && sha256sum -c SHA256SUMS)   # "da5_chosen.pt: OK" 가 나오면 정상
```

- 코드는 WSL 홈(`~/ai-optimizer`)에 받는다. `/mnt/c` 아래보다 빠르다.
- **Windows용 Git 이 아니라 Ubuntu 창에서 받는다.** Windows 에서 받으면 줄바꿈이 바뀌어 `.sh` 가 돌지 않을 수 있다.
- 적응 가중치(166 MB)는 100 MB 를 넘어 저장소에 없고 Release 에 있다. 이 파일이 없으면 `reproduce.sh` 가 5단계에서 멈춘다.

## 3. 파이썬 환경 (약 10분)

```bash
python3 -m venv ~/venvs/halio
source ~/venvs/halio/bin/activate
pip install --upgrade pip
pip install -r requirements.lock.txt --extra-index-url https://download.pytorch.org/whl/cpu
```

`python3 -m venv` 에서 `ensurepip is not available` 오류가 나면 `sudo apt install -y python3-venv` 를 한 뒤 다시 한다 (원 실험 PC 에서도 한 번 겪음).

`--extra-index-url` 은 torch CPU 판(2.14.1+cpu)을 받기 위해 필요하다. 이게 없으면 GPU 판 6 GB 를 받거나 설치가 실패한다.

## 4. 데이터 둘 곳 정하기

하드디스크가 D 드라이브라면:

```bash
echo 'export HALIO_DATA_DIR=/mnt/d/halio_data' >> ~/.bashrc && source ~/.bashrc
```

(드라이브 문자가 다르면 `/mnt/e/...` 처럼 바꾼다. 설정하지 않아도 D 드라이브가 보이면 `/mnt/d/halio_data` 를 자동으로 쓴다)

D 드라이브가 DVD·카드 리더처럼 쓸 수 없는 드라이브면 자동 선택이 실패한다(`/mnt/d/halio_data` 에서 `Permission denied` 또는 `Read-only file system`). 이때는 WSL 홈에 둔다:

```bash
echo 'export HALIO_DATA_DIR=~/halio_data' >> ~/.bashrc && source ~/.bashrc
```

`~/.bashrc` 에 적어 두면 새 터미널에서도 같은 위치를 쓴다.

## 5. 다운로드 없는 점검 (2~3분)

```bash
SELFTEST=1 bash run_pilot.sh
```

가짜 데이터로 전 과정을 돌아본다. 끝에 표가 나오면 환경은 정상(수치는 무의미).

## 6. 재현 실행 (약 2~4시간)

```bash
bash reproduce.sh
```

| 단계 | 내용 | 시간 (대략) |
|---|---|---|
| 1 | 데이터 다운로드 | 인터넷 속도에 따라 10~40분 |
| 2 | 분할 재생성 → 제출본 `splits/` 와 sha256 비교 | 1분 |
| 3 | FP32 ONNX export + P1 게이트(PyTorch 와 출력 일치) | 5분 |
| 4 | 양자화: A1 동적, SPL-b567-k32 (이상치 채널 분리 + 정적 INT8) | 5~10분 |
| 5a | 최종 구성: 적응 가중치 sha256 확인 → FP32 ONNX + P1 → 같은 SPL 처방 (`repro/da_build.sh`) | 5~10분 |
| 5 | COCO-confirm 검색 5구성 + CIFAR-100 test 5구성 | 1~2시간 |
| 6 | 속도·메모리 (다른 프로그램을 끄세요) | 10분 |
| 7 | 기대값과 비교 표 출력 | 즉시 |

- 정확도만 먼저 보려면 `SKIP_BENCH=1 bash reproduce.sh`
- 중간에 끊겨도 다시 실행하면 이미 끝난 단계는 건너뛴다
- 재현 결과는 `RP-` 가 붙은 이름으로 `results/` 에 저장된다
- `da5_chosen.pt` 가 없으면 5단계에서 "✘ … 가 없거나 sha256 이 다릅니다"로 멈춘다 → 2단계의 `wget` 을 다시 실행

### 6-1. 빠른 재현 (약 20~30분, 다운로드 약 0.3 GB)

```bash
bash repro_quick.sh
```

전체 COCO(815 MB) 대신 판정용 분할(confirm) 앞 500장과 캘리브 64장만 공식 주소에서 받고, CIFAR-100 test 는 앞 2,000장만 평가한다. A0·SPL-b567-k32·DA5-A0·최종 DA5-SPL 을 처음부터 다시 만들고 `repro/EXPECTED_QUICK.json` 과 비교한다. 갤러리가 500장이라 R@K 값은 보고서 값보다 높고, 기대값도 같은 조건에서 만들었다(10/20, 전체 실행의 저장 임베딩으로 계산한 값과 소수 넷째 자리까지 같음 확인).

### 6-2. 최종 시험 XM3600 (선택, reproduce.sh 다음에)

보고서 결과 요약의 대표 숫자(XM3600 R@1 41.66% → 51.71%, +10.05%p)를 다시 잰다. reproduce.sh 가 만든 모델과 적응 텍스트 상태를 쓰므로 **reproduce.sh 를 끝낸 뒤** 실행한다. 새 터미널이면 먼저 `cd ~/ai-optimizer && source ~/venvs/halio/bin/activate`.

- 받는 것: XM3600 사진·캡션(약 0.9 GB, 공식 주소) + **NoCaps 검증셋 사진 4,500장**(Hugging Face `lmms-lab/NoCaps`, 1 GB 넘을 수 있음). 주 지표는 NoCaps 와 겹치는 43장을 빼고 계산하는데, 그 목록을 만들려고 NoCaps 검증셋을 통째로 받는다.
- NoCaps 준비 스크립트는 `pyarrow` 가 필요해서, 메인 환경을 건드리지 않도록 별도 환경(`~/venvs/data`)에서 돈다.

```bash
M=$(python -m src.common models-dir); D=$(python -m src.common store-dir)/models_da5
python3 -m venv ~/venvs/data && ~/venvs/data/bin/pip install pyarrow huggingface_hub
~/venvs/data/bin/python src/nocaps_prep.py $(python -m src.common data-dir)/nocaps
python -m src.xm3600_prep download
python -m src.xm3600_eval text
python -m src.xm3600_eval text --tag da5 --text-model $D/text_state.pt
python -m src.xm3600_eval eval --i-know-final RP-A0=$M/clip_vitb16_image_fp32.onnx RP-DA5-SPL=$D/imp/SPL-b567-k32.onnx:da5
python -m src.xm3600_eval table --i-know-final --ref RP-A0 --codes RP-A0 RP-DA5-SPL
```

끝에 주 지표(3,557장) 표와 보조(전체 3,600장) 표가 차례로 나온다. 주 지표 부분은 이렇게 나와야 한다:

```
| RP-A0 | 41.66% | 68.13% | 76.69% | +0.00 [+0.00, +0.00] |
| RP-DA5-SPL | 51.71% | 78.35% | 85.34% | +10.05 [+9.02, +11.13] |
```

같은 표가 `results/xm3600.md` 에 저장된다.

## 8. 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| `pip install` 에서 torch 를 못 찾음 | 3단계의 `--extra-index-url` 을 붙였는지 |

| `$'\r': command not found` | 줄바꿈이 Windows 식으로 바뀜(Windows용 Git 으로 받았거나 Windows 편집기로 저장). Ubuntu 창에서 다시 `git clone` |

## 9. Hailo 부분 (선택)

- Hailo DFC 5.4.0 은 Hailo 개발자 사이트(로그인 필요)에서 받는다. **재배포 금지라 이 패키지에 넣지 않았다**
- 설치: DFC 5.4.0 휠을 `~/venvs/hailo` 에 따로 설치하고(파이썬 3.10, 메인 환경과 섞지 않는다) `export CUDA_VISIBLE_DEVICES=''` 로 CPU 만 쓴다 (**GPU 가 있으면 반드시 끌 것.** DFC 가 GPU 를 잡으면 최적화 단계가 달라져 결과가 바뀔 수 있다)
- 컴파일된 HEF 는 `model_files/` 에 있다. 다시 만드는 명령(`source ~/venvs/hailo/bin/activate` 후, 원본 가중치):

```bash
python -m dfc.split_hailo --blocks 7 --k 32 --split-fc1 --tag splf_b7_k32          # parse → 양자화 → 컴파일 → HEF
# 최종 적응 가중치로: 공식 형식 ONNX 에 적응 가중치를 넣은 뒤 같은 명령
python -m dfc.inject_da --models-subdir models_da5 --tag da5
python -m dfc.split_hailo --blocks 7 --k 32 --split-fc1 --tag splf_b7_k32_da5 --src-onnx <STORE>/hailo/official_da5.onnx
```

- 에뮬레이터 정확도: `python -m dfc.final_eval --har <STORE>/hailo/clip_vit_b_16_image_encoder.<tag>.quantized.har --code RP-H-... --i-know-final`
