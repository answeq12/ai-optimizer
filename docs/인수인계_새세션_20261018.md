## 3. 평가 설계 (고정)

- 주 평가: COCO val2017 자체 분할 텍스트→이미지 검색 R@1. **select 2,405장**(설정 고르기) / **confirm 2,406장**(봉인, 10/17 개봉 완료). 캘리브 합집합 189장(`splits/coco_ret_exclude.txt`)은 평가 제외
- 보조: CIFAR-100 검증 10k(train 에서 분리), CIFAR-100 test 10k(10/17 개봉 완료)
- 95% CI = 이미지 단위 짝지은 bootstrap 2000회. **마진 2%p** = R@1 차이 CI 하한 ≥ −2.0
- 선택 규칙: ① 마진 통과 → ② 빠른 것(5% 이내면 메모리→크기) → ③ R@1. 후보는 224 입력·**NPU 실행 가능한 정적 구성만**(동적 A1 계열은 비교 기준)
- 속도: CPU 4스레드, 배치 1, 워밍업 20 + 300회 × 3반복, p50/p95, 메모리 VmHWM. Hailo 속도는 **DFC 프로파일러 추정치(실측 아님)**
- confirm·test 는 `--i-know-final` 없이 안 열림. 이미 열었으므로 이후 결과는 전부 "사후 분석/추가 탐색"으로 표시

## 5. 핵심 발견 (보고서 근거)

1. 민감도(E05): fc2 12개 FP32 → 회복 100%. 블록별 b7 75% / b6 49% / b5 15%
2. 활성값(E08): fc2 입력 absmax b5 17 / b6 26 / b7 42, 이상치가 3~4개 채널에 집중. 99.9% 가 8비트 눈금 9칸만 사용
3. 대리 지표(E20): 캘리브 1회의 bulk_levels < 20 인 층 = 정확히 fc2 b5·6·7 (민감도 실험 상위 3개와 일치)
4. **레지스터 뉴런(E23)**: 이상치 토큰(이미지당 약 5개, 블록 5부터) 에서 켜지는 MLP 뉴런 상위 10개가 **모두 우리 hot 32채널 안**(9개는 top4). 이상치 = 어텐션 싱크용 고노름 토큰을 만드는 뉴런 (arXiv 2506.08010 과 일치)
5. Hailo 이상치 채널 격리(E21): fc2 만 나누면 실패(fc1+GELU 출력이 8비트 한 텐서) → fc1 부터 나눠 select 마진 통과, 컨텍스트 13 회복
6. **Hailo 캘리브 변동(E24, 사후)**: 캘리브 묶음 s0/s1/s2 에 따라 confirm 이 크게 흔들림

| confirm R@1 차이 | s0 | s1 | s2 | 평균 |
|---|---|---|---|---|
| H-official | −3.16 | | | |
| H-fc2b7 (층 전체 16비트) | −1.99 | −1.58 | −1.61 | −1.73 |
| H-splf-b7-k32 (동결) | −3.03 | −2.35 | −1.41 | −2.26 |

   → 동결한 s0 이 가장 나쁜 쪽이었음. 16비트 보호 구성은 전반적으로 select→confirm 약 1%p 하락. 보고서에는 3묶음 평균±범위로
