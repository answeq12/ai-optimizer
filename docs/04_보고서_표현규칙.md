# 보고서 표현 규칙

출처: 팀 공유 문서 `팀공유_진행정리_20261014.pdf` (10/14, 안세준) "보고서에서 피할 표현". 보고서·발표·노션에 수치를 쓸 때 지킨다.

## 과제를 말하는 방식

- 목표: 갤러리 사진을 기기 안에서 **영어 문장으로 검색**하고, 사진 색인(이미지 인코더)을 Hailo-10H로 가속한다
- 핵심 결론 3줄
  1. 정확도 손실의 원인은 6·7번 블록 fc2(MLP 축소층) 입력의 이상치 몇 채널이다. CIFAR로 찾았고 COCO 검색에서도 똑같이 확인했다
  2. 그 층만 높은 정밀도로 남기면 ORT·Hailo 둘 다 FP32와 거의 같은 검색 품질이 나온다(2%p 기준 통과)
  3. 대가는 속도다. Hailo 추정 속도가 221 → 170 fps(7번만) 또는 140 fps(6·7번)로 줄어든다. 보드 실측으로 확인할 예정

## 피할 표현 → 대신 쓸 표현

| 피할 표현 | 대신 쓸 표현 |
|---|---|
| "FP32를 넘었다", "102%" | "FP32와 차이 X%p [95% 범위]" |
| "갤러리 검색이 빨라졌다" | "사진 색인이 빨라졌다" (가속한 건 이미지 인코더) |
| "한국어 갤러리 검색" | "영어 문장 검색" |
| ORT에서 얻은 개선을 Hailo 개선처럼 서술 | 플랫폼별로 따로 보고 |
| 프로파일러 fps를 실측처럼 서술 | "프로파일러 추정치(실측 아님)" |
| 공개 COCO 1K/5K 수치와 직접 비교 | "자체 COCO val2017 분할(갤러리 약 2,400장)" |
| "Hailo보다 낫다", "Hailo 공식 수치와 같은 평가셋" | "같은 평가에서 Hailo 기본 설정 대비" |
| "A2 붕괴는 확실히 재현된다" | "우리 설정에서 관찰했다" |

- CIFAR 사진으로 보정한 Hailo 모델은 CIFAR 정확도는 올랐지만 실제 사진 검색에서 무너졌다(R@1 23.7%). CIFAR에서의 향상을 성과로 쓰지 않는다
- 마진을 select 결과를 본 뒤 정했다는 점을 숨기지 않는다
- 사실 / 가설 / 추측을 구분해서 쓴다. 실패한 실험도 "효과 없던 시도"로 남긴다
